# iPad WebView ラッパー MVP 要求仕様

最終更新: 2026-05-19

## 目的

- iPad 上でクリダスを WebView ラッパーアプリとして動かし、**Bluetooth レシート印刷つきの店頭運用** を MVP として検証できる状態にする
- まずは **店頭POS** と **注文管理画面** の運用成立を優先する

## 対象端末

- iPad
- 専用の WebView ラッパーアプリ上でクリダスを開く

## MVP で対象にする画面

### 1. 店頭POS画面

- `/store-pos/[token]`
- お客様が商品を選ぶ画面
- 注文完了後、店員が `料金受領を記録` したタイミングで自動印刷対象になる

### 2. 注文管理画面

- `/vendor/mobile-order/orders`
- 店員が注文確認、会計記録、再印刷を行う画面

## MVP で対象にする印刷導線

### 1. POS 受領後の自動印刷

- 店員が `料金受領を記録` を押す
- 会計記録は先に確定する
- レシート印刷設定が有効なら、iOS ネイティブ印刷 bridge に印刷要求を送る
- 印刷失敗時も、会計処理は失敗させない

### 2. 注文管理画面からの再印刷

- 受領済みの注文に対して `再印刷` ができる
- 再印刷の印字には `再印刷` マークを付ける

## MVP で対象にする印字内容

- header: 注文番号
- body: 注文内容
- footer: 店舗名 / 注文日時

## Web 側で持つべき前提

- 既存 `ReceiptPrintPayload` をそのまま利用する
- 既存の共通印字ドキュメント表現を再利用する
- Web 側は Bluetooth を直接制御しない
- Web 側は **iOS ネイティブ bridge に印刷要求を渡す** ところまで担当する

## ネイティブ bridge の前提

- 基本は `window.webkit.messageHandlers.kuridasPrinter.postMessage`
- fallback として `custom URL scheme` に載せ替え可能な構造を持つ

## MVP で非対象にするもの

- Safari 単体での Bluetooth 印刷
- 汎用ブラウザ対応
- App Store 一般公開
- 複数プリンターの自動切替
- 複数メーカー同時対応
- 売上帳票や分析レポートの印刷
- Bluetooth SDK 固有の最適化

## MVP の成功条件

1. iPad WebView ラッパー上で POS 画面を操作できる
2. `料金受領を記録` 後に、印刷要求をネイティブ bridge へ送れる
3. 注文管理画面から再印刷要求をネイティブ bridge へ送れる
4. 印刷失敗時も、会計や注文管理の操作は止まらない
5. 実機検証時に、店頭の 1 オペレーションを最後まで通せる
