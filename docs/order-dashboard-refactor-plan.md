# 注文管理画面リファクタ計画

## 目的

`/vendor/mobile-order/orders` は、現在ひとつのページコンポーネントに以下の責務が集中している。

- 初期データ取得
- 営業枠切替
- 一覧フィルタ / 並び替え
- 新着注文の検知
- 音声通知 / ハイライト管理
- 選択中注文の詳細取得
- optimistic update
- UI 表示

この状態だと、UI を少し変えるだけでも影響範囲が広く、ローディング改善や不具合修正の見通しも悪くなりやすい。  
そのため、注文管理画面を「一覧」「詳細」「通知」「更新」の単位で分解し、体感速度と保守性を同時に改善する。

## フェーズ

### フェーズ1

- 新着通知 / 音声通知 / ハイライトを custom hook に切り出す
- 一覧フィルタ / 並び替え / 件数定義を helper に切り出す
- ページ本体は「状態をつなぐ役割」に寄せる

### フェーズ2

- 注文一覧の取得 / 件数取得 / 詳細取得の状態管理を hook に切り出す
- 営業枠切替と定期更新の責務を hook 側に集約する
- optimistic update の共通化を進める

### フェーズ3

- 注文詳細のステータス操作 / 通知送信 / 料金受領を action hook 化する
- 一覧 / 詳細 / 集計の再取得条件をさらに細くする
- 必要なら Server Component と Client Component の境界も見直す

## 完了条件

- `orders/page.tsx` の責務が UI 組み立て中心になっている
- 新着通知や一覧計算ロジックが別ファイルで再利用 / テストしやすい
- 店員向け UI 改修時に、一覧計算や通知処理を触らずに済む
- 体感上のローディングと再描画の揺れが減っている

## 今回の実装対象

- フェーズ1 を実施する
