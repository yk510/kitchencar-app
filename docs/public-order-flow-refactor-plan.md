# 公開注文 / POS 共通注文フロー リファクタ計画

## 目的
- 公開注文ページと POS 画面にある重複ロジックを減らす
- オプション選択、金額計算、在庫不可判定の挙動差分を防ぐ
- UI 改修時に、片方だけ壊れるリスクを下げる

## 対象
- `src/components/PublicMobileOrderPageClient.tsx`
- `src/components/StorePosPageClient.tsx`

## フェーズ

### フェーズ1: 共通ロジック抽出
- 商品選択の初期状態
- 必須/単一/複数オプションの検証
- オプション込みの単価・行合計計算
- 選択済みオプションの整形
- 在庫不可判定
- 在庫バッジ表示

### フェーズ2: 画面遷移まわり整理
- 確認ページへの遷移
- 注文完了後の状態リセット
- 在庫再取得後の選択状態補正

### フェーズ3: カート UI / 表示整形整理
- カート要約文言
- 注文確認表示
- 完了画面の注文詳細表示

## 今回の実装方針
- まずはフェーズ1を進める
- UI 文言差分は残して、判定ロジックだけ共通化する
- 既存の payload / API 契約は変えない
