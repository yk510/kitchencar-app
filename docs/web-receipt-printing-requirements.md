# Webアプリ前提 レシート印刷 要件整理

最終更新: 2026-05-18

## 1. 目的

既存の Web アプリベースの

- 店頭POS
- モバイルオーダー注文管理

から、**レシートまたは注文控えを印刷できるようにする**。

今回の主目的は、

- POS 注文時に注文番号を紙で渡せる
- 店員が注文内容を紙で確認できる
- 将来の会計・オペレーション改善の土台を作る

ことです。

---

## 2. 前提

### 2-1. アプリ前提

- 現行プロダクトは **Web アプリ** である
- iPad Safari などのブラウザ利用を前提とする
- ネイティブアプリ化は今回対象外

### 2-2. 接続前提

- **Bluetooth 直結は採用しない**
- **LAN 接続のレシートプリンター** を前提とする
- iPad とプリンターは同一ネットワーク上に置く

### 2-3. 対象プリンター方針

MVP では、以下どちらか 1 系統に寄せる。

- Epson TM-m30III-H 系
- Star mC-Print3 系

ただし、実装の第一候補は **Epson ePOS Print 系** とする。

理由:

- Web アプリからの HTTP ベース印刷と相性が良い
- ブラウザ運用での実装難度が比較的低い

---

## 3. MVPで実現すること

### 3-1. 印刷対象

MVP では以下を対象にする。

1. **店頭POS注文の受付控え**
- お客様向け
- 注文確定後に印刷可能

2. **店員用の注文控え**
- キッチン向け / 作業向け
- 注文管理画面から再印刷可能

### 3-2. 印字内容

最低限必要な内容:

- 事業者名
- 注文番号
- 注文日時
- 商品明細
- 数量
- トッピング / オプション
- 各行金額
- 小計
- 支払方法
- 合計金額

あればよい内容:

- 店舗名
- 出店場所
- イベント名
- 注意書き

### 3-3. 印刷タイミング

#### POS

- お客様が注文確定した後
- 店員が `料金受領を記録` した後
- 店員が注文管理画面から再印刷したい時

MVP 推奨:

- **まずは注文管理画面から手動印刷**
- その後、必要に応じて POS 完了後の半自動印刷へ拡張

#### モバイルオーダー

- MVPでは必須にしない
- 将来的に注文管理画面からの再印刷に含められる形にしておく

---

## 4. 画面要件

### 4-1. 注文管理画面

追加する要素:

- `レシート印刷`
- `控えを再印刷`

表示条件:

- POS 注文を中心に表示
- 将来的にはモバイルオーダーにも適用可能な設計にする

### 4-2. POS完了画面

MVP では、以下のどちらかで良い。

1. 印刷は店員画面で行う
2. 完了画面に `印刷準備中` / `印刷できない場合は店員へ` の案内を出す

ブラウザ制約を考えると、**最初は店員側起点の印刷** が安全。

---

## 5. 技術方針

### 5-1. 印刷方式

Web アプリから、プリンターに直接 HTTP でレシートデータを送る。

候補:

- Epson ePOS-Print XML
- Star WebPRNT

MVP 第一候補:

- **Epson ePOS-Print**

### 5-2. 実装構成

1. フロント:
- `印刷する` ボタン
- 印刷リクエスト送信
- 印刷中 / 成功 / 失敗 UI

2. サーバー:
- 印刷 payload 生成
- 注文情報からレシート XML / command 生成
- プリンター送信

3. プリンター:
- LAN 上の固定 IP または設定済み URL

### 5-3. 保存したい設定

ベンダー単位:

- プリンター利用有無
- プリンターメーカー
- プリンター接続先 URL / IP
- 自動印刷有無

営業枠 / 端末単位で後から欲しくなる可能性:

- 利用プリンター名
- 端末ラベル

## 6. MVPで後続に回すもの

- Bluetooth 直接印刷
- キャッシュドロワー連携
- キッチンプリンターと会計プリンターの分離
- 複数プリンター同時出力
- 自動再試行キュー
- 印刷履歴 UI
- レシート法対応の厳密な会計帳票

---

## 7. 成功条件

- 店員が注文管理画面から POS 注文の控えを印刷できる
- 注文番号・明細・金額が正しく出る
- iPad + LAN プリンター環境で安定運用できる
- 失敗時に画面上で再印刷できる
