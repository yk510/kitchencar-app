# Android + Bluetooth プリンター MVP 検証 要件整理

最終更新: 2026-05-19

## 目的

- Android タブレットと Bluetooth レシートプリンターを使って、店頭POSの注文番号控えを安価に発行できるか検証する
- 現在の Web アプリ構成を大きく壊さず、現場導入に十分な体験を作れるかを見極める
- 将来、iPad / Safari とは別トラックで Bluetooth 印刷を育てるための実装方針を固める

## 検証前提

- 端末は **Android タブレット固定**
- ブラウザは **Chrome 系** を前提
- 対応プリンターは **1機種に絞る**
- まずは **一般公開配布ではなく、MVP の現場検証用**
- クリダス本体は **Web アプリのまま維持**

## 今回の課題

- iPad / Safari の Web アプリでは Bluetooth 印刷の自由度が低い
- キッチンカー現場では、LAN プリンターより **モバイル Bluetooth プリンター** の方が取り回しがよい
- ただし Web ブラウザだけで Bluetooth 印刷を安定運用するのは難しい

## MVP の到達目標

1. 店頭POSの注文番号を、Bluetooth プリンターで印字できる
2. 店員が `料金受領を記録` したあと、控え発行までの流れが止まらない
3. 印字内容は最低限次を含む
   - 注文番号
   - 注文内容
   - 店舗名
   - 注文日時
4. 印刷失敗時も、会計記録自体は止めない
5. 再印刷ができる

## 対象機能

- 注文管理画面からの再印刷
- POS 注文の会計確定後の印刷
- Bluetooth プリンター接続確認
- 印刷失敗時の再試行

## 対象外

- iPad / Safari 対応
- App Store / Google Play 一般公開
- 複数プリンターの自動切替
- 複数メーカー同時対応
- 売上分析や帳票の印刷

## 技術方針

MVP では次の 2 段階で考える。

### 方針A: Android Chrome + Web Bluetooth を先に検証

- もし対象プリンターが Web Bluetooth で安定して扱えるなら最短
- 補助アプリなしで進められる可能性がある
- ただし、機種依存・実装依存が強い

### 方針B: Android 補助アプリを用意する

- Web アプリは印刷 payload を作る
- 補助アプリが Bluetooth 通信を担当する
- Web 単体より安定しやすい
- 実務上はこちらが本命になりやすい

## プリンター候補

MVP では **1機種固定** が前提。

候補観点:
- Android での Bluetooth 接続安定性
- レシート幅 58mm / 80mm
- 充電や持ち運びのしやすさ
- コマンド送信仕様の確認しやすさ

候補例:
- SII `MP-B20`
- Star のモバイル系

## Ticket 1 で固定する検証構成

### Android タブレット

- **Redmi Pad SE（Wi-Fi モデル）**

採用理由:
- 11インチで、店頭POSの 2 カラム UI を確認しやすい
- Android Chrome での検証端末として無難
- 価格帯を抑えやすく、MVP 検証用に導入しやすい
- 日本国内でも比較的入手しやすい

### Bluetooth プリンター

- **SII MP-B20**

採用理由:
- 小型でキッチンカー運用に向く
- 日本国内で扱いが多い
- Bluetooth / USB に対応
- Android SDK 系の案内があり、将来的に補助アプリ方式へ進む時も相性が良い

### 検証時の固定条件

- Android タブレットは `Redmi Pad SE`
- プリンターは `SII MP-B20`
- ブラウザは Android 版 Chrome
- まずは 1 台のタブレット、1 台のプリンターで検証
- 印字幅は **58mm 前提**

### 判断メモ

- Web Bluetooth だけでいけるかを最初に試す
- 不安定なら、対象プリンターは固定したまま **Android 補助アプリ方式** に切り替える

## 端末候補

- Android タブレット
- 10〜11インチ
- Chrome が安定
- Bluetooth 接続が安定
- 端末は MVP 中は固定

## 印字内容の優先順位

- header: 注文番号
- body: 注文内容
- footer: 店舗名 / 注文日時

## 失敗時の運用

- 印刷失敗でも `料金受領を記録` は成功させる
- 印刷エラーは画面上に表示する
- 店員は `再印刷` で再試行できる
- 必要なら、注文番号だけを画面上で大きく維持して fallback する

## MVP で確認したいこと

1. Android タブレット + Bluetooth プリンターで本当に安定するか
2. 受領後の印刷遅延が現場で許容できるか
3. 再接続やスリープ復帰が現場で扱えるか
4. Web Bluetooth だけで足りるか、補助アプリが必要か
